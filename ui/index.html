System-wide results on an exposed held-out set — not this trial alone

How well does HOPTRACE actually localize faults?

These numbers are read unchanged from held_out_results_4b.json: the Phase 4b configuration scored on the same 12 trials as the earlier Phase 4 run. Those traces had already been inspected while the Phase 4b detector variants were designed, so this is a historical record of what the frozen configuration scored — not an independent validation. The only independent result so far is Phase 4, which missed the false-attribution limit (3 of 12 = 25% against a 10% maximum).

What this system cannot yet do

  • Recall is 50%. Of eight trials with a real injected fault, HOPTRACE's frozen detector raised a claim in four. It stays silent rather than guess on the rest.
  • Loss and bandwidth faults are not localized. Across the 4 loss/bandwidth trials in the exposed held-out set and the 4 in the Phase 4b tuning set, the frozen detector localized none. It was developed against latency and jitter behaviour. Whether bandwidth limits can be observed at all with the current light probe traffic is not yet established; any bandwidth-localization claim stays unproven.
  • This evaluation is not independent. The held-out set was inspected during Phase 4b design, so no result here validates the frozen detector on unseen data. A fresh, sealed evaluation has not been run.
  • "No significant degradation" means no onset was detected — it does not rule out a fault that covers most of the observation window, or a measurement with too little data. The system has no separate "insufficient data" result yet.
  • The 1.5s alignment window (δ_align) is fixed, not empirically validated against independent ground-truth propagation delay — it is a disclosed, reasoned choice, not a measured constant.
  • Sample sizes are small. Twelve trials, of which four were localized, cannot certify a production system. Confidence intervals on every rate above are wide.
  • Confidence scores are a fixed, disclosed heuristic — corroborating-hop fraction × completeness — not a calibrated probability model.

Methodology

Six linear Linux network namespaces, tc/netem fault injection with ground truth isolated from the localization engine at the OS permission level, a shared CLOCK_MONOTONIC clock between prober and app client, and an onset detector selected on tuning data. Its Phase 4b configuration was then scored on a held-out set that had already been inspected during design (see the evaluation section).
